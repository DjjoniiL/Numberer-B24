# Нумератор сделок - свои правила генерации Project Specification

## Назначение

`Нумератор сделок - свои правила генерации` — статическое Bitrix24 Marketplace-приложение для автоматической записи уникального номера в сделки.

## Финальная Версия

- UI/runtime label: `Нумератор сделок - свои правила генерации v.4`
- Worker label: `Нумератор сделок worker v.4`
- Marketplace zip: `dist app B24 zip/Numberer B24 v.4.zip`
- Статус: логика `v.3.18` проверена на тестовом портале во всех трёх режимах и финализирована как `v.4`.

## Ключевые Правила

- Номер записывается в пользовательское поле сделки `UF_CRM_UNIQUE_NUMBER`.
- Название поля в карточке: `Уникальный номер`.
- Формат номера: `PREFIX_AAA0001`.
- Разделитель `_` автоматически ставится между префиксом и буквенной частью, если префикс не заканчивается на `_` или `-`.
- Префикс берётся из ручной настройки или из выбранного строкового поля сделки.
- Цифровая часть: 3, 4, 5 или 6 символов.
- Буквенная часть: 2, 3, 4 или 5 латинских букв.
- Режимы генерации: последовательный и случайный.
- Режим `Свой стартовый номер` позволяет задать первое значение без префикса сделки.
- При вводе стартового значения приложение автоматически подстраивает выбранную длину буквенной и цифровой частей.
- Дата начала выборки ограничивает обработку сделок условием `DATE_CREATE >= startDate`.
- При сохранении настроек обрабатываются только подходящие сделки с пустым полем `Уникальный номер`.
- Сделки, где `Уникальный номер` уже заполнен, сохраняют прежнее значение и не очищаются.
- Удалённые или недоступные сделки отсекаются дополнительной проверкой через `crm.item.get`.
- Фоновый worker продолжает активную ревизию нумерации и отдельно обрабатывает новые подходящие сделки без номера.

## Доступ

- Изменять настройки может только администратор портала.
- Для проверки используется `BX24.isAdmin()` и fallback `user.admin`.
- Неадминистратор видит сообщение: `Для изменения настроек обратитесь к администратору вашего портала.`

## Настройки По Умолчанию

- Префикс: ручной.
- Ручной префикс: `NUM`.
- Цифровая часть: 4 символа.
- Буквенная часть: 2 символа.
- Режим: последовательный.
- Дата начала выборки: дата установки минус 14 дней.
- Стадия по всем воронкам: успешная стадия.

## Поведение При Пустом Префиксе Из Поля

Если администратор выбрал источник префикса из поля сделки, но в конкретной сделке это поле пустое:

- номер не создаётся;
- поле `Уникальный номер` не заполняется;
- в таймлайн сделки добавляется комментарий;
- повторный комментарий для той же ревизии настроек не дублируется.

## Журнал Логирования

Журнал открывается кнопкой `Журнал логирования` и показывает последний результат обработки.

Обязательные блоки лога:

- `settings`
- `selection`
- `processing`

При открытом журнале включается вертикальный скроллинг приложения.

## Права Bitrix24

Минимальные scope:

- `crm`
- `placement`
- `user_brief`

`user_brief` достаточно, потому что приложение не читает профили пользователей, контакты, e-mail или телефоны. Пользовательский scope нужен только для проверки административного доступа через `user.admin`, если `BX24.isAdmin()` недоступен.

## Правило По Архивам

Zip-архивы не коммитятся и не пушатся по умолчанию. Допускается добавить один, максимум два финальных или релизных архива, только если пользователь явно разрешил пуш zip-архива.

Для версии `v.4` пользователь явно разрешил: `запушь zip v.4`.
