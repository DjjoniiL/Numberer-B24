# Numberer B24

`Numberer B24` — статическое Bitrix24 Marketplace-приложение для автоматической выдачи уникальных номеров сделкам.

Финальная версия: `Numberer B24 v.4`.

Финальный Marketplace-архив: `dist app B24 zip/Numberer B24 v.4.zip`.

Статус: логика версии `v.3.18` проверена на тестовом портале во всех трёх режимах работы и финализирована как `v.4`.

## Назначение

Приложение добавляет в сделку поле `Уникальный номер` (`UF_CRM_UNIQUE_NUMBER`) и заполняет его по правилам администратора портала. Номер помогает быстро идентифицировать сделки, использовать внутреннюю нумерацию компании и формировать предсказуемые номера с префиксом.

## Что Делает Приложение

- Создаёт пользовательское строковое поле сделки `Уникальный номер`, если его ещё нет.
- Добавляет поле `Уникальный номер` в основную карточку сделки.
- Загружает все воронки сделок через Bitrix24 CRM.
- Позволяет выбрать стадию запуска отдельно для каждой найденной воронки.
- Позволяет выбрать дату начала выборки.
- Создаёт номер только для сделок, которые попадают в выбранную стадию и имеют дату создания не раньше даты начала выборки.
- Не перезаписывает старые номера: если поле `Уникальный номер` уже заполнено, значение сохраняется.
- Поддерживает ручной префикс.
- Поддерживает префикс из выбранного строкового поля сделки.
- Если источник префикса выбран из поля сделки, а значение в сделке пустое, номер не создаётся и в таймлайн добавляется комментарий с причиной.
- Поддерживает последовательный и случайный режимы генерации.
- Поддерживает режим `Свой стартовый номер`.
- При вводе своего стартового номера автоматически подстраивает количество букв и цифр под введённое значение.
- Сохраняет настройки в `app.option`, поэтому они не сбрасываются после обновления страницы.
- Показывает журнал логирования, который можно открыть и скрыть.
- Содержит окно `Помощь по приложению` с описанием логики и кнопкой чата Открытой линии.

## Формат Номера

Базовый формат:

```text
ПРЕФИКС_ББЦЦЦЦ
```

Пример:

```text
FBR_AA0001
```

Состав номера:

- `FBR` — префикс сделки.
- `_` — разделитель, добавляется автоматически, если префикс не заканчивается на `_` или `-`.
- `AA` — буквенная часть значения.
- `0001` — цифровая часть значения.

Доступные длины:

- Буквенная часть: 2, 3, 4 или 5 латинских букв.
- Цифровая часть: 3, 4, 5 или 6 цифр.

При настройках по умолчанию доступно примерно `6,76 млн` комбинаций на один префикс: `26 × 26 × 10 000`.

## Настройки По Умолчанию

После установки пользователь получает такие настройки:

- Префикс: вручную, значение `NUM`.
- Формат номера: `NUM_AA0001`, затем `NUM_AA0002`, `NUM_AA0003` и так далее.
- Буквенная часть: 2 латинские буквы.
- Цифровая часть: 4 цифры, диапазон `0001-9999`.
- Режим: последовательная генерация.
- Дата начала выборки: минус 14 дней от даты установки.
- Стадии запуска: успешная стадия в каждой найденной воронке.

## Режимы Работы

### Ручной Префикс

Администратор задаёт значение префикса вручную, например `FBR`. Все новые номера создаются с этим префиксом.

Пример:

```text
FBR_AA0001
FBR_AA0002
FBR_AA0003
```

### Префикс Из Поля Сделки

Администратор выбирает строковое поле сделки. Для каждой сделки приложение берёт префикс из этого поля.

Если значение поля пустое:

- номер не создаётся;
- поле `Уникальный номер` остаётся пустым;
- в таймлайн сделки добавляется комментарий с описанием ошибки.

### Свой Стартовый Номер

Администратор включает переключатель `Свой стартовый номер` и вводит буквенную и цифровую части номера без префикса сделки.

Пример стартового значения:

```text
FSA008790
```

Если ручной префикс равен `FBR`, итоговый первый номер будет:

```text
FBR_FSA008790
```

Следующие номера продолжают последовательность от указанного значения.

## Правила Обработки Сделок

При нажатии `Сохранить` приложение:

1. Сохраняет настройки в `app.option`.
2. Создаёт новую ревизию правил нумерации.
3. Выбирает сделки по воронке, стадии и дате создания.
4. Проверяет, что сделка активна и доступна через CRM API.
5. Пропускает сделки, где `Уникальный номер` уже заполнен.
6. Создаёт номер только для подходящих сделок с пустым значением.
7. Сохраняет состояние последовательности, чтобы следующие номера продолжались корректно.

Удалённые или недоступные сделки не должны получать номера. Для защиты от таких записей перед записью номера приложение дополнительно проверяет сделку через `crm.item.get`.

## Журнал Логирования

Кнопка `Журнал логирования` открывает и скрывает лог внутри приложения.

В журнале отображаются:

- `settings` — сохранённые настройки;
- `selection` — фильтры выборки по воронкам и стадиям;
- `processing` — статистика обработки и создания новых номеров.

При открытом журнале приложение включает вертикальный скроллинг, чтобы можно было просмотреть полный лог.

## Доступы В Интерфейсе

Настройки может менять только администратор портала.

Проверка выполняется через:

- `BX24.isAdmin()`;
- fallback `user.admin`, если SDK не вернул административный статус напрямую.

Неадминистратор видит уведомление:

```text
Для изменения настроек обратитесь к администратору вашего портала.
```

## Права Bitrix24

Минимальные scope:

- `crm`
- `placement`
- `user_brief`

`user_brief` достаточно, потому что приложение не читает профили, контакты, e-mail или телефоны пользователей. Этот scope используется только для проверки административного доступа через `user.admin`, если это требуется.
